# Omarchy Display Workspaces Lite

**A read-only per-display workspace widget for the Omarchy menubar.**

**Plugin ID:** `display.workspaces.lite` · **Version:** 1.1.0

> **Caution — AI-generated by GPT Astra.** This plugin's custom implementation and documentation were developed with AI under human direction, building on Omarchy code. Treat it as experimental, review the code, and use it at your own risk.

## What it does

- Groups workspaces beneath their current or configured display.
- Shows workspaces declared by HyprMonCfg even before Hyprland creates them.
- Tracks the visible workspace on each display and keyboard-focused workspace separately.
- Highlights the display containing the pointer.
- Lets you name displays, choose icons, and order display groups in the menubar.
- Remembers each display's name, icon, and order with its connector and, when available, unique make/model/serial identity.

Right-click a display label to manage presentation preferences. The panel shows connected displays as a horizontal menubar-order strip with explicit move controls. A separate remembered-display picker edits names and icons for connected or disconnected displays and can forget obsolete associations with confirmation. Preferences save through Omarchy's native shell settings API, remain independent of profiles, and stay stored while a display is disconnected.

## What it does not do

This plugin never changes:

- monitor position, mode, scale, transform, VRR, mirroring, or enabled state;
- workspace rules or workspace-to-display assignments;
- HyprMonCfg profiles or generated configuration;
- suspend, resume, lid, dock, or hotplug policy.

HyprMonCfg and Hyprland remain the only display/workspace configuration writers.

## HyprMonCfg workspace compatibility

Quickshell's live workspace model contains instantiated workspaces only. A nonpersistent rule such as workspace 6 or 9 can therefore be absent from the bar until first opened.

Display Workspaces Lite reads these three interfaces without writing anything:

```text
hyprctl -j monitors
hyprctl -j workspaces
hyprctl -j workspacerules
```

It merges live positive-number workspaces with enabled exact positive-number rules. Live placement wins. Rule targets are accepted only when they identify one enabled, non-mirrored display by exact connector name or unique exact `desc:` identity. Broad, named, special, ambiguous, disabled, and invalid rules are ignored.

Clicking an uncreated declared workspace asks Hyprland to open it; Hyprland and HyprMonCfg's rule decide its display.

## Install

```bash
omarchy plugin add https://github.com/nephilus/omarchy-display-workspaces-lite.git --enable
```

To place it on the left:

```bash
omarchy plugin enable display.workspaces.lite --section left
```

After confirming Lite works, disable the full plugin and stock workspace widget if present:

```bash
omarchy plugin disable display.workspaces
omarchy plugin disable omarchy.workspaces
```

Do not run the full and Lite variants as competing workspace bars unless that duplication is intentional. Their plugin IDs and presentation settings are separate; Lite does not automatically migrate names/icons/order from `display.workspaces`.

## Requirements

- Omarchy's native Quickshell plugin system
- Hyprland and `hyprctl`
- Python 3 standard library
- HyprMonCfg is recommended but not required; ordinary exact Hyprland workspace rules work too

No daemon, systemd unit, dependency package, profile store, or background service is installed.
